# MADR テンプレート

`adr-writer` skill の最終フェーズで、この構造に沿って `docs/adr/` 配下にADRを生成する。
各セクションは、対応するフェーズでユーザーが確定した内容のみを記載する。未確定の推測は書かない。

## 採番規則

- ファイルパス: `docs/adr/NNNN-slug.md`
- `NNNN`: 4桁ゼロパディングの連番（`0001`, `0002`, ...）。`docs/adr/` 配下の既存ファイルのうち最大の番号 +1 を採番する。ファイルが1つも存在しない場合は `0001` から開始する
- `slug`: 決定内容を要約した英小文字のケバブケース（例: `choose-database-engine`）。決定タイトルが日本語の場合も、意味を保ったまま英語スラッグへ変換する

## テンプレート

```markdown
# {ADRのタイトル。決定内容を1文で表す名詞句}

## Status

{proposed | accepted | rejected | deprecated | superseded by [NNNN-slug](NNNN-slug.md)}

## Context

{この決定が必要になった背景・課題を2〜3文で記述する。問題を疑問文の形で定式化してもよい}

## Decision Drivers

- {判断に影響する制約・関心事1}
- {判断に影響する制約・関心事2}
- ... <!-- 数は状況に応じて増減する -->

## Considered Options

- {選択肢1のタイトル}
- {選択肢2のタイトル}
- ... <!-- 数は状況に応じて増減する -->

## Decision Outcome

採用する選択肢: 「{選択肢のタイトル}」。理由: {他の選択肢では満たせない決定要因、またはトレードオフ比較の結果を明記する}。

## Consequences

- {この決定によって生じるポジティブな影響}
- {この決定によって生じるネガティブな影響・今後対応が必要な事項}
- ... <!-- 数は状況に応じて増減する -->
```
